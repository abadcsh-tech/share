Obsidian

옵시디언은
'디스플레이어' 입니다.

내 컴퓨터에 저장된 평문 .md 파일을 — 사람이 읽기 좋은 모습으로 그려서 보여주는 것. 그 이상도, 그 이하도 아닙니다.

파일은 옵시디언의 것이 아닙니다. 옵시디언이 사라져도, .md 파일은 그대로 남습니다.

왼쪽이 실제 .md · 오른쪽이 옵시디언이 본 화면

sermon.md Markdown

Claude Code

Claude Code는
'생산자' 입니다.

터미널에서 자연어로 부탁하면 — 글·노트·코드를 .md 파일로 출력합니다.

그 출력은 곧바로 옵시디언 볼트에 떨어지고, 옵시디언이 즉시 그려줍니다.

Live Demo

"자연어" 한 줄이
한 장의 .md가 됩니다.

Terminal ~/csh_remote
새 파일 — 출력 2026-05-04.md
핵심 통찰

두 도구는 서로 다른 일을 하지만,
같은 .md 파일을 봅니다.

Claude Code가 만들고 → 옵시디언이 읽고 → 우리가 옵시디언에서 다듬고 → 다시 Claude Code가 변환합니다.
모두 .md 한 장을 가운데 두고 돌아갑니다.

왜 MD인가 · 1

AI는 평문을 가장 잘 읽습니다.

Markdown

평문 · 텍스트
AI 가독성100%
  • AI가 구조를 한 번에 이해
  • 토큰 효율이 가장 높음
  • 변환·요약·재구성 자유

PPTX / DOCX

바이너리 · 폐쇄적
AI 가독성35%
  • 구조 정보가 형식 안에 갇힘
  • 파싱이 깨지기 쉬움
  • 이미지·텍스트가 분리되지 않음
왜 MD인가 · 2

한 번 닫힌 포맷은,
다시 열리지 않습니다.

Markdown → 모든 포맷

출구가 열려 있다
변환 성공률98%
  • → PPT · PDF · DOCX · HTML 모두
  • 레이아웃 깨짐 거의 없음
  • 한 원본에서 N개 출력

PPT → 다른 포맷

출구가 막혀 있다
변환 성공률22%
  • PPT를 Word로 → 깨짐
  • PPT를 HTML로 → 거의 불가
  • 매번 처음부터 다시 작업
왜 MD인가 · 3

MD가 사라질 가능성은
매우 낮습니다.

Markdown

오픈 표준 · 30년+
장기 보존95%
  • 특정 회사에 종속되지 않음
  • 설령 바뀌어도 변환이 쉬움
  • 가장 대중적 → 미래 호환 유리

독자 포맷

회사·앱 종속
장기 보존40%
  • 앱이 사라지면 파일도 위태
  • 버전 업그레이드마다 호환 깨짐
  • 옮길 때마다 한 번 더 변환 단계
메인 소스의 문제

"메인 소스가 .md로 되어 있지 않으면,
나머지 파일들은 그저 호환되지 않는 섬으로 존재한다."

PPT를 한 번 만들어두면 — 그것은 그저 PPT일 뿐입니다.
MD에서 PPT로 가는 길은 열려 있고, 거꾸로 가는 길은 막혀 있습니다.

Workflow

전체 흐름은
이렇게 작동합니다.

1
Claude Code로 만든다

"이번 주 설교 노트 정리해줘" — 자연어 한 줄이면 정돈된 .md가 출력됩니다.

2
옵시디언이 그려준다

같은 폴더(볼트)를 옵시디언이 읽어 — 위키링크·태그·그래프뷰까지 살아 있는 노트로.

3
옵시디언에서 직접 다듬는다

위키링크 걸기, 메모 추가, 본문 다듬기 — 모두 옵시디언에서. 파일은 여전히 .md.

4
다시 Claude Code에게 변환을 부탁한다

"PPT로 만들어줘", "교사용 DOCX로 묶어줘" — 같은 원본에서 필요한 형식만 그때그때.

5
원본은 하나, 출력은 무한

주일은 PPT, 월간 자료는 DOCX, 공유는 HTML, SNS는 인포그래픽 — 모두 같은 .md에서.
